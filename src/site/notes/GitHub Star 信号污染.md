# GitHub Star 信号污染

[[GitHub\|GitHub]] Star 信号污染指 star 数从“开发者关注/收藏信号”变成可购买、可营销、可套利的指标后，对开源选型、投资筛选、招聘背书和安全判断造成的失真。

## 观察

- Star 最初更接近书签和轻量认可，但在 AI/LLM 开源项目热潮中被赋予了融资、采购、媒体报道和招聘背书功能。一个低成本可购买指标一旦能换钱，就会被系统性操纵。
- 刷星会惩罚真实项目：认真维护、缓慢增长的仓库可能被漂亮 README、短期暴涨和机器人 issue 的项目压过，从而影响开发者选型和投资人 sourcing。
- 真正的开源热度通常不只发生在 star 数上，还会留下 commit 连续性、真实 issue/PR 对话、作者历史、HN/Reddit/X/博客中的技术讨论和下游使用痕迹。
- 基础识别信号包括 fork-to-star 比、贡献者-to-star 比、stargazer 账号画像、star 增长曲线、commit 密度和外部讨论质量。单看 star 绝对值已经不足以判断项目可信度。
- 对 [[AI Agent 安全\|AI Agent 安全]] 来说，刷星不是单纯营销问题。agent 如果把 GitHub star 当作依赖选择或工具可信度信号，就可能被污染的开源热度误导。
- 对 [[人工智能超级个体\|人工智能超级个体]] 和早期 AI 创业生态来说，刷星说明“可见指标”会迅速变成套利对象。政策、投资和加速器需要更重视可复现产品、真实用户和代码审计。

## 边界

- 来源列出的价格、规模和个案属于媒体转述和研究摘要，具体仓库判断需要用原始论文、StarScout 等工具和 GitHub 数据复核。
- 低 fork/star 或新账号 stargazer 不是定罪证据，只是尽调信号。
