# OpenClaw

OpenClaw 是“AI as Infrastructure”语境下的智能体平台节点。它在教学场景中被部署为学生智能体、教师智能体和课程实践基础设施，也在交通、城管、公园等城市治理场景中被表述为“大脑 + 手脚”的数字员工架构。

## 观察

- 在[[OpenClaw 上海交大课堂部署\|OpenClaw 上海交大课堂部署]]中，OpenClaw 从个人体验变成整班支撑：45 个学生智能体与 1 个教师智能体同时运行，形成平行于现实课堂的虚拟教室。
- 课程中的 OpenClaw 不只是“让学生用一个工具”，而是让学生智能体、教师智能体和课程知识库形成持续互动。它把 [[实证研究智能体工作流\|实证研究智能体工作流]] 中的 agent 能力前移到教学基础设施。
- 致远一号提供了校内算力、模型 API、闭环部署和并发环境；这一基础设施关系由[[OpenClaw 上海交大课堂部署\|OpenClaw 上海交大课堂部署]]事件页承接。
- 城市治理场景中的 Claw/Dclaw 叙事把摄像头、传感器、音箱、人员和系统组织成可协同智能体，用于“看见-决策-执行-反馈”闭环。这与 [[智能社会治理\|智能社会治理]] 直接相邻。
- OpenClaw 和 [[Hermes Agent\|Hermes Agent]] 一起说明 agent 框架正在从个人效率工具扩展到课程、组织和城市系统。关键不再只是会聊天，而是能接入工具、记忆、场景规则和执行回路。

## 边界

- 截至 2026-08-10，上海交通大学 OpenClaw 校园应用中心及案例中心足以确认课堂、科研、管理和校园 Skill 等校内应用入口；本轮在交大官方入口未取得能独立核验交通、城管、公园项目数量或“全国首个”的具名项目文件。因此城市治理内容只保留为原来源口径，不从校园案例反推；仅在具名政府/业主文件、招采或验收记录、第三方案例出现时重开。
- 课堂部署记录可以支持教学基础设施观察，但不能直接推出学习效果、研究产出或学生能力提升结论。

## 三同关系线索

- 校园机构关系经[[OpenClaw 上海交大课堂部署\|OpenClaw 上海交大课堂部署]]事件节点承接：项目、学校、技术执行部门和算力平台之间是一次公开部署协作，不是项目的行政隶属、投资或知识产权关系。
- 同事/组织线索只写课程设计、技术执行和课堂参与的公开角色。学生智能体不是学生本人节点，未具名人员也不据此建立私人同事关系。
- 上海校园与城市治理是两类应用场景；课堂部署证据不能反向证明交通、城管或公园项目已经由同一批机构实施。
